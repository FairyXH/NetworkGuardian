# 蒸馏协议

这是网络效用回归，不是自然语言生成。教师负责结合网络知识标注，本机软件负责样例、数据冻结、训练、留出验证、部署和回滚。不得用模型自己的预测充当新证据。

## 工具顺序

1. `training_status {}` 列出任务、当前模型哈希、特征顺序和限制。恢复与本次授权有关的 labeling / paused / running / ready 任务；不要接管无关任务。
2. 新建：`model_distill {"action":"create","requestId":"<run标识>-001","teacher":"<实际Agent/模型名称>","count":160,"epochs":300}`。相同 requestId 返回同一任务，即使其他参数不同。记录 jobId；同一 run 后续批次使用递增后缀。
3. `training_examples {"jobId":"...","limit":16}`。默认只返回未标注项。每次保持 offset=0，投喂后列表会缩短。需要较少调用时批量提高到 32，最多 64。不要在列表缩短时增加 offset 导致漏项。
4. 逐条分析，`model_distill {"action":"label","jobId":"...","labels":{"<id>":{"target":0.35,"confidence":0.7,"rationale":"丢包较高，虽信号强但不适合稳定联网"}}}`。每批最多 64 条。重试保持原 id 和标签；不能提交任意特征或冒充本机实测。
5. 标注全部样例后 `model_distill {"action":"start","jobId":"..."}`。立即返回，不表示完成。后台每 5 epochs 原子保存检查点，每次只运行一个任务。不要把 count/epochs 变大当成更高质量。
6. 用 `training_status {"jobId":"..."}` 查询，间隔 2–10 秒；避免高频空转。running 等待，paused 调 start，failed 先看 error（磁盘/数据错误连续失败三次则停止并报告），ready 查看 evaluation。可用 pause 暂停并保留进度。
7. 留出指标通过时调用 deploy，核对 state=deployed、deployedHash；必要时再次查 debug_model。工具会在部署时重新验证。基线哈希过期意味着个人学习已变化：保留当前模型，从最新基线新建任务，不能绕过比较或直接写权重。
8. 如果当前任务未通过，不部署、不修改已冻结标签追逐验证分数。新一批使用不同场景；连续两次未改善停止。对同一验证集重复调参会高估效果。
9. 需要回滚时 `model_distill {"action":"rollback","jobId":"...","expectedHash":"<deployedHash>"}`。只允许当前模型仍是该部署版本；部署后的个人学习或后续部署会拒绝回滚，避免丢失新数据。不删除仍需回滚的部署任务。

## 特征与教师判断

features 的八个输入依次为：

|位置|含义|理解方式|
|---|---|---|
|0|质量分 /100|0 差、1 好；是综合质量指标|
|1|失败率|0 无失败、1 全失败；真实聚合优先 TCP，缺失时使用网关丢包|
|2|min(延迟毫秒 /500, 1)|1 表示至少 500ms，不表示精确 500ms|
|3|min(抖动毫秒 /100, 1)|1 表示至少 100ms|
|4|信号强度 /100|仅无线信号，不代表外网质量|
|5|实测置信度|低值意味着证据不足|
|6|当前外网在线|0/1；合成场景中的条件，不是实际探测|
|7|偏好强度|0..1；未知默认 .5，不得据此虚构用户习惯|

source=synthetic 是服务器生成的假设场景；可能有“信号强但失败率高”等组合，按输入条件推理，不当作本机故障事实。source=observed-aggregate 是创建任务时捕获的近期聚合实测：至少 5 组、5 分钟内、对应当前 SSID/网卡/频段，附 observedAtUtc。为减少身份信息，不导出 SSID、设备名或密码。延迟未知默认 100ms、失败率未知默认 .1、偏好未知默认 .5；实际观测须至少存在 TCP 失败率或网关丢包。

target 是 0..1 的联网效用，越大越适合承载流量，不是成功概率。可参考：不可用/严重失败通常 0.02–0.2；频繁失败或高延迟通常 0.2–0.5；普通可用通常 0.5–0.75；稳定、低失败、低延迟通常 0.75–0.98。按综合条件调整，避免只根据单一质量分或信号决定。偏好影响应适度，不能抵消严重丢包/离线；低置信度输出保守。confidence 表示教师对自身标签的把握，不能因是 Agent 回答就全部设为 1。rationale 简短解释决定因素，最多 500 字符。

教师无需调用另一模型；若用户明确授权外部教师，可使用其指定 API，但只发送数值场景和必要网络知识，不发送凭据。不要将密钥写进 Skill、脚本、任务标签或仓库。

## 验证的含义

相同特征哈希固定分组，约 20% 留出、至少 16 条留出和 48 条训练。训练开始冻结数据，留出不参与梯度更新。训练目标按 confidence 混合教师标签与内置专家规则，教师最大占比 75%。

部署要求：候选留出教师 MAE ≤0.20，较基线至少改善 0.0005；256 条独立专家场景 MAE ≤0.12，较基线退化不超过 0.015；模型参数有效且当前模型仍与任务基线一致。指标是对教师/专家数值评分的拟合，不是独立实际联网成功率，不能报告为“准确率 99%”。

保持禁用、SSID 强制指定、采样门槛和有限模型影响仍由实际决策策略控制；不能通过蒸馏标签改变这些规则。删除用户问答会按保留问答从内置种子重建模型；重置学习也会清除已部署模型效果，已有任务基线随之失效。

每个任务存储在应用数据目录 distillation/<jobId>.json，含教师标签、候选、基线和回滚模型，有 .bak。无需自行写这些文件；保留原子保存与来源链。最多 64 任务、512 样例/任务，不再需要且未部署的任务可用 delete 清理。

## 稳定性和停止条件

每轮报告样例数、训练 epochs、两种 MAE、部署/未部署原因；没有新实测时明确标为知识蒸馏，不声称学到了新用户习惯。重复请求超时先查 status，重用原 requestId 或相同标签。若服务不可达，进行至多三次有间隔的连接重试；仍失败保留 jobId 和下一步，等待软件恢复。不要无限重启设备、关闭学习、放宽部署门槛或重置模型来绕过错误。
