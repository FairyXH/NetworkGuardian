# 全接口质量评分与训练数据

## 开发检查点

- 统一接口/网络身份，兼容旧 Wi-Fi 历史；有线、无线、隧道、虚拟及其他接口均使用实测质量规则。
- 对未连接、回环、无可用探测地址、无公网路由的接口明确说明适用范围；不把虚拟局域网或回环当公网断网，不伪造实测分数。
- 持续采样、报告、接口状态、问答上下文及蒸馏观测样本共用匹配规则，防止网络变化后串用历史。
- 公网端点连接失败不是物理丢包；公网 ICMP 过滤不直接扣成断网；无无线信号的网络使用中性信号特征。
- 保留现有 8 维模型及训练/部署门槛，训练样本增加网络类型和身份的可追溯元数据，不虚构主观标签。
- 完成单元、原生探测及隔离 EXE 验证后，备份桌面旧 EXE、请求原进程退出、等待 WFP 规则释放、同名替换，再启动并验证真实采样及报告。

## 当前实现

以接口 GUID、网络类型和当前网络身份隔离历史。已知 Wi-Fi 保留原 SSID/频段历史；其他接口的网络身份包含当前地址、网关及 DNS 的指纹，地址或上游变化后先重新采样，不能借用旧网络高分。旧历史、答题集和 8 维模型继续兼容，不重置个人更新。

所有存在外网路径的 Ethernet、Wi-Fi、Tunnel、Virtual、Other、Unknown 接口均使用相同实测规则。路由识别覆盖 IPv4/IPv6 默认路由及 VPN 常用的 /1 分流默认路由；IPv6-only 接口通过绑定源地址和 IPv6 接口索引的 TCP 批次采样，不冒用 IPv4 测量。IPv6 目标优先使用配置中的同族端点，没有配置时使用 [Cloudflare 官方 IPv6 DNS 地址](https://developers.cloudflare.com/1.1.1.1/ip-addresses/) 的 53 端口。未连接、无可用地址、纯本地虚拟网络和回环会逐项报告原因，不伪造公网分数。

评分由网关 ICMP 未回应比例、已校准的外网 TCP 失败率、有限权重的公网 ICMP、端点响应时间及抖动计算，保留近期/长期平滑。连续失败且同期独立权威探测确认离线时，即使过去没有 TCP 成功记录也会判为较差；未经确认的端点阻断不直接等价为物理丢包。未测量吞吐量，不能将分数理解为带宽或游戏服务器延迟。

每个接口最多保留 120 批历史，近期估计使用 30 分钟内最多 40 批；正式评级至少 5 批、5 分钟内更新且有网关或 TCP 有效证据。新网络先按 5 秒间隔补足基础样本，之后遵循用户采样周期；差链路加快至 15 秒。最多并发两块接口，每个外网 TCP 目标重复两次估计响应变化；IPv4 保留网关与公网 ICMP 小批次。

运行概览逐接口展示评分、依据和测量限制，有线详情页显示同一历史摘要。接口状态中的 `qualityScore` 是实测评分；模型效用加成单独存储，在已有有线优先策略内有限影响同类型物理接口排序，不拿模型输出冒充测量值，不接管 VPN/虚拟网卡路由。

## 模型数据及个人学习

`training_status.observations` 返回当前可用于蒸馏的所有类型真实观测；创建训练任务采用同一捕获函数。观测附带网络类型、接口标识、网络指纹、显示名称及采样时间。特征维度及顺序保持不变；非 Wi-Fi 信号使用中性 0.5，无线使用真实信号。过期、断开、身份已变化、有效证据不足或非法数值的记录不进入样本。

样本保留 `observed-aggregate` 来源，不虚构教师标签；合成样本继续单独标识。一般网络体验/优先级问答上下文包含各类型网络，用户真实回答可以为有线等网络产生有边界的个人学习更新。Wi-Fi 专属的网卡分配题仍只使用无线候选。原有留出集、验证门槛、哈希并发保护及部署/回滚保持生效。
