# 故障排查与报告问题

先保留错误时间、软件版本和实际返回，再定位链路。需要更改设备或恢复数据时，参考 [维护说明](maintenance.md)。

## 最小排查顺序

1. 确认实际运行的 EXE 版本、配置根和进程；旧版仍在托盘时，新启动可能并非新实例。
2. 查看“运行概览”的质量报告、默认出口和接口探测，区分设备、无线关联、IP、网关与外网。
3. 核对保持禁用、SSID 指定、暂停/自动恢复、校园网时段、凭据及失败冷却。
4. 按错误时间和接口过滤诊断日志，结合下发结果和后续探测；任务卡出现记录不等于成功。
5. 通过 MCP 可先查 `guardian_status`、`quality_report`、`devices_list`、`debug_decision`，再按需查日志，避免一开始就重启设备或重置模型。

## 常见情况

| 现象 | 检查与处理 |
| --- | --- |
| 没看到窗口 / 关闭后进程仍在 | 查看托盘及隐藏图标；默认关闭到托盘，退出使用托盘菜单 |
| 找不到网卡 | 对比 Windows 是否识别设备，检查驱动、设备分类、隐藏/虚拟设备显示及日志；虚拟网卡不提供物理控制 |
| 扫描为空或没有 SSID/BSSID | 核对接口、无线电、驱动状态；Windows 11 检查定位服务和桌面应用位置权限，之后再扫描 |
| 不连接一个可见网络 | 检查 Windows Profile / 凭据、SSID 绑定、保持禁用、名单、校园网时段、占用冲突、失败黑名单及冷却 |
| 企业网络重复失败 | 核对 EAP 方法、身份、证书/服务器名及凭据应用结果；检查重试上限，修改条目后再核对真实结果 |
| Wi-Fi 已连接但不能上网 | 分别看关联、DHCP/IP、网关、认证门户和该接口外网探测，不用链路 Up 或信号强度代替外网结论 |
| 浏览器正常但探测失败 | 检查默认出口、代理/VPN/TUN、按接口探测、Npcap 和原始探测设置；VPN kill switch 可能禁止物理接口直连，按实际需求配置，不据此断言网卡损坏 |
| 网关 ICMP 无回应 | 可能禁用 Echo，应结合 TCP、其他目标及采样历史；不要把从未回应的目标直接当成丢包 100% |
| USB 网卡长期较差 | 按网卡/SSID/频段检查失败、延迟、抖动和样本数；需要时保持禁用，不能仅凭 USB 身份判断优劣 |
| 指定网卡后其他卡不接这个 SSID | 这是硬绑定预期；目标卡离线时也不会自动改给其他卡，需明确取消或变更指定 |
| Windows 手动启用后又被禁用 | 检查软件的保持禁用规则；暂停自动恢复不会解除它，应在软件内取消 |
| 已保存禁用但设备仍启用 | 分别检查规则保存与系统操作、UAC、驱动错误、是否要求重启以及延迟重试日志 |
| 设置似乎未保存 | 检查保存结果、配置路径、实际进程、加载/规范化日志；点击保存并应用立即确认，不用旧草稿覆盖新的无线页修改 |

## 出口切换证据

以下为只读 Windows 查询：

```powershell
Get-NetAdapter | Format-Table Name, Status, LinkSpeed
Get-NetRoute -AddressFamily IPv4 |
  Where-Object DestinationPrefix -eq '0.0.0.0/0' |
  Format-Table ifIndex, NextHop, RouteMetric, InterfaceMetric
Get-NetIPInterface -AddressFamily IPv4 |
  Format-Table InterfaceAlias, InterfaceIndex, ConnectionState, InterfaceMetric
```

多条路由比较需同时考虑 RouteMetric 和 InterfaceMetric，不要仅按其中一列猜默认出口。再结合程序记录的实际出口和源地址探测；代理可能使应用出口与直连探测不同。

验收“有线链路正常但 WAN 故障”时，应在已明确允许的测试窗口保持电脑 LAN 连接，使用独立上游的已保存备用 Wi-Fi，通过路由器 WAN 断开/恢复观察失败、备用出口和回切。拔电脑网线或禁用以太网测的是链路断开，不能代替 WAN 故障测试。测试会影响网络，日常诊断不必主动制造故障。

常规探测模式下存在连续成功/失败和稳定观察窗口；Npcap 原始探测优先且有权威结果时可能即时判定。先核对当前设置与证据，再判断“没有立即切换”是否异常。修改恢复策略前保留日志，不要通过连续手动断连加重状态混乱。

## MCP 连接与操作

1. 软件必须运行，设置显示 MCP 已开启且正在监听。
2. 使用当前端口的 `http://127.0.0.1:<端口>/mcp`，客户端支持 Streamable HTTP；旧式 SSE 路径不适用。
3. 端口占用时界面返回错误，不会自动换端口。修改端口后更新客户端；远程、WSL、容器的回环地址通常不指向 Windows 软件进程。
4. Host / Origin 不符合本机同端口规则会被拒绝；不要通过把监听改成所有网卡来绕过。
5. 只读健康检查为 `GET /health`。`GET /mcp` 返回 405 是当前无 SSE 传输的预期，不代表 POST 工具调用不可用。
6. 连接超时后先读状态再决定是否重试。网卡操作和认证命令不能盲目重放；配置保存、操作成功和外网可用分别核对。

默认凭据查询隐藏密码和自定义 XML；`includeSecrets=true` 显式读取可解密密码与 XML，不用于普通调试。日志工具默认是内存快照，不能代替完整滚动日志。

## 问答、神经网络和训练

| 情况 | 解释与下一步 |
| --- | --- |
| 回答增多但 PersonalSteps 少 | 不同问题有不同学习用途；缺少有效实测的答案只作为软标签，不能以题数等同梯度更新次数 |
| 模型更新后没有换网 | 稳定连接、硬绑定、禁用规则、质量与可信度门槛可能阻止切换；检查实际决策而非只看参数 |
| 训练 start 返回后没结果 | start 仅受理后台任务，用 training_status 看状态、epoch、error 和 evaluation |
| 软件重启后 paused | 检查点已恢复，用同一 jobId 调 start；Agent 断线本身不会停止正在运行的软件内训练 |
| 部署被拒绝 | 留出/专家门槛失败或当前模型已改变；保留现有模型，不手改哈希或冻结后的标签追分 |
| 回滚被拒绝 | 部署后出现个人学习或其他部署，原版本哈希不再匹配；不能覆盖这些新数据 |
| 任务损坏 | 保留 json、bak 和错误，退出后备份整个数据根，再恢复一致备份，不直接删除唯一训练资料 |
| 达到任务数上限 | 用 delete 清理无用未部署或已被后续部署替代的任务，保留当前部署与运行任务 |

MAE 是与教师/专家效用标签的差异，不是真实网络准确率。完整状态转换、输入特征及停止条件见 [训练协议](../skills/networkguardian/references/training.md)。

## 报告问题时提供

- EXE 版本、提交（若自行构建）、Windows 版本，以及是否从旧版升级。
- 复现步骤、发生时间、期望行为、实际行为和是否稳定复现。
- 相关物理网卡、SSID/频段、默认出口、VPN/代理/Npcap 状态，按需匿名化标识。
- 相关开关、绑定/禁用规则、操作返回及必要时段的过滤日志。
- MCP 问题附工具名、错误及脱敏参数；训练问题附 jobId、state、epoch 和 evaluation。
- 说明已验证和未验证部分，例如只有模拟设备测试、尚未测试真实认证。

不需要提供 Wi-Fi 密码、密钥或完整凭据库；配置中的命令参数、自定义 XML、网络导出和日志共享前应检查。备份与恢复遵循 [维护文档](maintenance.md)，不要先重置学习或删除整个数据目录再取证。
