# WFP 出口切换阻断

## 实现约束

- 仅调用 Windows 自带 `Fwpuclnt.dll` 用户态管理接口，不安装驱动。
- 与重启旧网卡互斥；保留现有仅清理 IPv4 TCP 的兼容选项，默认不启用新行为。
- 新默认出口生效后，仅阻断旧物理网卡地址上的 TCP/UDP，覆盖 IPv4/IPv6。
- 使用动态会话，禁止持久或开机规则；部分创建失败时回滚，退出时释放。
- 提权助手监视主进程生存、取消信号、出口恢复及最长租期；不能依赖 UI 正常退出才能清理。
- 默认阻断 5 秒；可观测到原 TCP 连接或明确绑定旧地址的原 UDP 端点仍存在时延长，最长 60 秒。
- UDP 端点存在只表示 socket 尚未关闭，不能证明仍在通信；通配地址绑定也不能可靠归属旧网卡。到期释放并记录观察限制，不无限阻断。
- 测试只对测试进程的专用端口下发规则，验证 TCP/UDP、IPv4/IPv6、正常释放和进程终止清理，不阻断真实业务。

动态规则随所属进程会话结束清除，且不持久化到下次开机；强制关机不会使这批规则在重启后继续阻断。运行时仍应检查当前租期、主进程和出口状态，及时释放无必要规则。

## 使用及兼容性

在“自动管理 → 出口切换连接迁移 → 出口切换处理方式”选择 WFP。另两个选项为原有的仅清理 IPv4 TCP、重启旧物理网卡。新功能默认关闭，不会自动改动已有运行实例的配置。

WFP 和网卡重启均作用于旧出口所有进程，不采用 TCP 白名单/黑名单。WFP 默认最短 5 秒、最长 60 秒，可分别配置为 1～30 秒和最短值～120 秒。仅在观察到真实默认出口变化后启动，不在应用启动时盲目阻断其他网卡；自动恢复暂停或关闭时不启动 WFP。

每次操作由同一 EXE 的管理员助手持有动态会话；主程序身份用 PID、启动时间及映像路径核对。退出、暂停、保存配置、再次切换出口会取消原任务；助手每秒检查请求文件、主进程、默认路由及地址归属。旧地址重新成为相应地址族的默认出口、地址消失或主程序退出时立即结束租期。主程序不能终止提权助手时，取消通过删除请求文件传达，另有最长租期兜底。

IPv4/IPv6 分别核对默认出口。IPv4 切走而 IPv6 仍留在旧网卡时，不阻断仍为 IPv6 默认出口使用的地址。回环、通配、IPv6 链路本地/组播及 IPv4 映射地址不能作为生产过滤目标。只创建本次动态会话的独立子层和规则，不枚举或删除其他软件的防火墙规则。

助手协议升级为 v4，增加 WFP 操作和主程序启动时间。旧的 TCP 清理协议参数继续保留；主程序和助手应使用同一构建。
