# 2026-10-18：恢复、路由与 TCP 清理修复

本次针对运行监测发现的探测停滞、路由指标反复变化、TCP 清理 Win32=317 三项问题。当前改动为 0.14.0 基线上的候选构建，不替换已运行程序，也不宣称完成真实网络长期回归。

## 恢复动作期间继续探测

主循环原先等待扫描、连接、认证等动作完成才进入下一轮探测。认证等待期间，路由看门狗虽刷新快照时间，却继续引用旧探测，导致“快照新、探测旧”。

新增 `MonitoredOperation` 在工作线程执行恢复动作，等待期间按到期时间继续探测。显式探测动作不叠加第二次探测；取消或观察失败时取消并等待原动作结束。完成后以最新接口、无线连接和全局探测构建快照。外部命令超时仍由原命令配置控制，命令完成不等于联网恢复。

## 路由写入统一与恢复观察

决策循环和路由看门狗改为共用一个指标执行入口，在同一信号量内读取当前接口、重新计算目标并核对漂移；已经由另一入口完成的调整不再重复写入，也不执行排队动作携带的旧指标。

之前权威原始探测使用“一次失败、一次成功、零恢复等待”，绕过配置中的恢复观察期。现在保留权威失败的快速降级，恢复时遵守 `InternetRecoveryThreshold` 和 `InterfaceRecoveryHoldSeconds`。首次启动发现在线路径不额外等待。真实链路变化仍可能产生必要的指标调整，不能承诺从此没有任何 Metric 变化。

## TCP 清理使用提权助手

微软 [SetTcpEntry 文档](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-settcpentry) 明确将返回码 317 列为未提权情况；原实现直接记录 API 返回值，并非误用了 GetLastError。

普通权限进程改用现有提权助手执行批量清理。助手协议升级为 v3，增加旧地址、迁移配置及关闭计数；通过已有源生成 JSON 元数据传输。调用前与助手提权后均重新验证地址属于已被替代的物理网卡，拒绝回环、未知地址、当前默认出口及无默认路由状态。主进程已提权时也执行同样的旧地址核对。

跳过 PID 0、监听、TIME_WAIT 等无活动归属连接；连接在枚举后自行消失时不计为清理成功。删除返回成功后重新读取连接表，仍存在则报告失败；TCP 表读取失败显式报错，避免把读取失败当作空表。拒绝提权/失败后五分钟内不重复触发提权请求。TCP 迁移在独立受跟踪任务中执行，避免 UAC 或清理拖住每秒路由看门狗；在一次清理尚未结束时跳过后续迁移请求，并记录调试信息。清理完成不证明应用重连或会话连续性。
